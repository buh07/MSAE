Morphological Sparse Autoencoders

This presentation explains the full MSAE project in simple English for people who know the basics of AI and machine learning, but are not deep in mechanistic interpretability.

Paper 1 concept gate cleared K=2 trainer works at 1B tokens PCC bridge program is active

Main result in one sentence: on Pythia-160M residual activations, especially layer 3, the project found a robust way to separate a smaller position dictionary from a larger content dictionary, and then trained that two-branch system stably through a full 1B-token run.

Important nuance: the strongest current win is cleaner separation and specialization, not universal improvement on every metric.

Main idea

Instead of asking one sparse autoencoder to explain every kind of structure inside a model, MSAE gives different kinds of structure their own branches.

Current strongest evidence

The project has strong evidence that position and content can be separated cleanly on Pythia-160M, especially at layer 3.

Where the project stands

Paper 1 is partially realized in experiments. Paper 2 and Paper 3 are still planned. A new bridge program now asks whether syntax lives in a shared crossover signal.

Experimental Question

What question is the whole project trying to answer?

Core scientific question

Can transformer activations be understood better if we split them into multiple kinds of structure, instead of forcing one dictionary of features to explain everything?

First concrete version

Can we separate where a token is from what the token is inside the residual stream of a language model?

Longer-term version

If that works, can the same idea grow into richer decompositions that handle dense residual structure, hierarchical features, and multi-dimensional features?

Why this matters

Sparse autoencoders are supposed to give us human-usable features. But recent work showed that standard SAEs often overlap too much, change a lot across random seeds, miss useful downstream signal, and leave a large structured residual unexplained.

The project hypothesis: some of those failures happen because the model is being forced to compress very different kinds of structure into one feature system.

What counts as success right now

  • Show that position and content are separable before full MSAE training.
  • Train a two-branch MSAE stably at scale.
  • Show that the branch-separation regularizer changes geometry in a real way.
  • Find out whether useful linguistic structure is purely private to one branch, or partly shared.
Plain English Basics

SAE vs MSAE in one minute

What is an activation?

An activation is the model's internal numeric state at some point in the network. You can think of it as a high-dimensional summary of what the model is "thinking about" right then.

What is a sparse autoencoder?

A sparse autoencoder tries to rebuild that activation using only a small number of learned feature directions. In plain English: it tries to explain a messy vector using a short list of reusable parts.

What is a dictionary here?

A dictionary is just the library of possible feature directions. One dictionary means one shared toolbox for every kind of structure the model contains.

What makes MSAE different?

MSAE uses multiple dictionaries in parallel. Each branch gets to specialize, and the training objective pushes the branches not to collapse into the same solution.

Input activation

Take one internal vector from the language model.

Branch 1

Try to capture position-like structure.

Branch 2

Try to capture content-like structure.

Low overlap pressure

Penalize branches if they become too similar.

Recombine

Add both branches back together to reconstruct the original activation.

Position

Information about where a token sits in the sequence.

Content

Information about the identity or meaning-carrying side of the token.

Incoherence

How much the branches overlap. Lower is better if we want the branches to specialize.

FVU

Fraction of variance unexplained. Lower means the model is reconstructing activations better.

Related Work

Why MSAE exists at all

The project is a direct response to several negative or cautionary results about standard sparse autoencoders. The goal is not "a new architecture because new architectures are fun." The goal is "fix specific things that look broken."

Feature absorption

Standard SAEs can merge parent and child concepts together, which makes features look cleaner than they really are.

Seed instability

If you retrain with a different random seed, many "features" do not come back. That weakens the idea that the dictionary is finding one canonical truth.

Weak downstream probes

On many tasks, probing SAE features performs worse than probing raw activations directly with logistic regression.

Dark matter

A large part of the residual error is still linearly predictable from the input. That suggests the SAE is not just missing a few sparse features. It may be missing a whole different kind of structure.

Multi-dimensional features

Some circuits seem to use circles or other structured geometric objects, not one-dimensional feature directions. A one-direction SAE may shatter those into fragments.

Closest baseline families

The project compares itself conceptually to JumpReLU SAEs, TopK SAEs, BatchTopK, and Matryoshka SAEs, with Matryoshka treated as a key later baseline.

The older theory behind the idea

MSAE borrows from morphological component analysis in signal processing: if different kinds of structure are sparse in different bases, it can be easier to separate them with multiple dictionaries than with one.

Important framing: the project is not claiming that all SAE problems are solved already. It is testing whether "multiple specialized dictionaries" is a better starting point than "one dictionary tries to do everything."

Experiment Set 1

Raw-activation separability pilot: test the premise before training MSAE

1

Question

Do the raw activations already show signs that position-related and token-related information live in different directions?

2

Method

Train simple linear probes on raw activations only. One probe predicts token position. Another predicts token identity. Then turn those probe weights into low-dimensional subspaces.

3

Key test

Project the activation into the position subspace and the token subspace. If the theory is right, position should survive much better in the position subspace, token identity should survive much better in the token subspace, and the subspaces should not lie on top of each other.

4

Why this experiment matters

If this pilot fails, then training a full two-branch MSAE may be solving the wrong problem. So this pilot is a de-risking gate, not a side quest.

What the pilot checked in plain English

  • Can a "position-only" projection still predict where the token is?
  • Can a "content-only" projection still predict what the token is?
  • Does each projection hurt the other job enough to show real separation?
  • Are the two subspaces separated by meaningful angles, instead of being almost the same thing?

Interpretation rule: the early raw-activation runs were useful, but the project treats the final pre-K2 suite as the authoritative gate because the early criteria and tooling changed during development.

Experiment Set 2

Pre-K2 full suite: decide whether real two-branch training is justified

After the pilot stage, the project ran a larger and more disciplined suite whose whole job was to answer one question: Is the position-vs-content split robust enough to justify full K=2 MSAE training?

What was swept

Layers 3 and 4, ranks 8, 16, and 32, multiple random seeds, and multiple dataset split modes.

What "holdout" means here

IID means ordinary in-distribution testing. Source holdout changes the text source. Corpus holdout checks whether the signal survives a broader data shift.

What the suite is really asking

Is the separation just a fragile artifact of one setup, or is it reproducible across seeds, layers, and data splits?

Why the rank sweep matters

Rank controls how many directions are allowed in the probe-derived subspace. If the split is real, there should be a good zone where the representation works, and then a boundary where it stops looking clean.

The project wanted a clean boundary, not just a best-case number. A strong scientific result looks better when success at the good ranks and failure at the boundary rank are both clear.

Why layer choice matters

Too early in the model and the representation may be too shallow. Too late and everything may already be heavily mixed together. The project treated layer 3 as the likely best site, but kept layer 4 as a fallback candidate.

Experiment Set 3

K=2 training runs: from smoke tests to a 1B-token wave

What the training stage is trying to answer

  • Can a two-branch MSAE be trained stably instead of collapsing?
  • Can the code checkpoint, resume, and scale cleanly?
  • Does the incoherence regularizer really make the branches more different?
  • What tradeoff, if any, appears between separation and reconstruction quality?

Simple explanation of the run design

  • Start with small smoke and resume tests so the trainer itself can be trusted.
  • Run a 100M-token wave to check stability before the largest run.
  • Run a 1B-token wave with three regularized seeds and one matched no-regularizer control.
  • Watch reconstruction, branch overlap, and active-latent usage all the way through.

What Was Separated

Be explicit: what activations were separated, and into what?

The strongest current supported result is not "we solved all models." It is much more specific: on the residual-stream activations of Pythia-160M, especially layer 3, the project found a robust position-vs-content demixing regime and trained a two-dictionary MSAE in that regime.

The model and site

  • Model: EleutherAI/pythia-160m-deduped
  • Primary site: residual stream, layer 3
  • Fallback site: residual stream, layer 4
  • Why this site: it keeps strong positional signal while still containing rich token/content structure

The two learned dictionaries

  • Position dictionary: 8,192 atoms, TopK = 8
  • Content dictionary: 32,768 atoms, TopK = 24
  • Meaning of that asymmetry: the project gives the content side much more capacity than the position side on purpose
  • Regularizer: cross-branch incoherence pressure so the two dictionaries do not collapse into the same feature family

Main low-dimensionality claim

The pre-K2 gate works cleanly at low headline ranks 8 and 16, and then fails at boundary rank 32. In plain English: the project found evidence that the position side lives in a relatively small subspace compared with the richer content side.

What that does not mean

It does not mean the entire model is only 8 or 16 dimensional. It means the probe-visible positional structure used for the gate appears to be concentrated in a small number of directions.

Why the larger content dictionary makes sense

Token identity, lexical variation, and semantics are much more varied than pure position. So giving content 4x as many atoms as position is not arbitrary; it matches the hypothesis that content needs more representational capacity.

Clear version of the main point: the project found a setting where one smaller, sparser dictionary can specialize toward positional structure while a larger dictionary carries the more varied content side, instead of forcing both jobs into one shared latent pool.

Concrete Examples

What do the two dictionaries seem to be doing in practice?

The repo currently gives its strongest concrete evidence at the branch and task level, not as a finished catalog of named individual atom cards. So the most honest examples are task-level behaviors of the learned position/content representations.

Important honesty note: the current project record supports strong claims about what the position dictionary and content dictionary do as groups. It does not yet contain a polished set of individual “this exact atom means X” case studies for the K=2 model.

Example 1: entity-type information is much more content-side than position-side

On the PCC follow-up tasks, content-private representations beat position-private ones very clearly on semantic labeling.

  • FewNERD coarse binary: content-private 0.8965 vs position-private 0.7541
  • WikiNeural English binary: content-private 0.9453 vs position-private 0.7570
  • WNUT17 type-only: content-private 0.1994 vs position-private 0.1508

Interpretation: if you want entity-type-like information, the content dictionary is the far more useful place to look.

Example 2: some syntax is not owned by one branch alone

For syntax-facing tasks, the best result often comes from using the branches together, not from treating either private branch as fully sufficient.

  • POS tagging family: mean joint gain about +0.0057 in A1c
  • Coarse dependency labels: mean joint gain about +0.0049 in A1c
  • B-light controls: syntax_pos stays positive under full, token, and coarse position controls

Interpretation: syntax-like structure seems partly interaction-based, which is exactly why the PCC bridge program now exists.

Example 3: not every "language" property is position-heavy

A naive story would say “the position dictionary handles syntax.” The repo does not support that simple version. In several PCC tables, the content-private branch is the stronger single private branch even on some syntax-facing tasks.

Interpretation: this is useful, not disappointing. It tells us the split is subtle: pure position is one component, rich content is another, and some relational structure may need both.

What a position-side atom family likely buys you

  • A smaller, lower-rank home for where-in-sequence information
  • A branch that can be separately regularized and separately tested
  • A cleaner way to ask “what happens if we suppress positional structure?”
  • A way to avoid letting positional signal dominate a general-purpose content dictionary

What a content-side atom family likely buys you

  • Much more capacity for token identity and lexical/semantic variation
  • A natural home for content-private semantic tasks like NER-style labeling
  • A branch that can absorb varied token-conditioned structure without pretending it is “just position”
  • A clearer way to test what stays intact when position-like structure is separated off
Why This Helps

Concrete benefits of the two-dictionary setup compared with a normal SAE

Question Normal single-dictionary SAE Current K=2 MSAE setup
Where does position live? It is mixed into one shared latent pool and has to be separated after the fact. There is an explicit branch intended to specialize toward positional structure.
Where does content live? It competes directly with position and everything else for the same dictionary budget. It gets its own larger dictionary and higher-capacity branch.
How do we test specialization? Mostly post-hoc: inspect mixed latents and try to cluster or relabel them. Directly: compare branches, clamp branches, ablate the incoherence term, and inspect private vs joint behavior.
Can we tell whether the split is real? Harder. A clean post-hoc story can still come from a mixed latent pool. Easier. The no-regularizer control and the branch-level audits test whether the split survives without just being storytelling.
Does the capacity match the hypothesis? No. One pool has to serve low-dimensional position and high-variation content at once. Yes. The design intentionally uses a small/sparse position side and a larger content side.

Benefit 1: branch identity itself is useful scientific structure

Even before individual atom cards exist, the split into position and content dictionaries gives the project a built-in experimental language: private position, private content, joint, and residual.

Benefit 2: the architecture matches the asymmetry in the data

Position appears lower-dimensional and more compressible. Content is broader and more varied. A normal SAE hides that asymmetry; MSAE encodes it directly.

Benefit 3: it exposes new questions a normal SAE blurs away

The PCC results are a good example. Once position and content are partially separated, you can ask whether syntax lives in one branch, the other, or in their interaction.

Most concrete current advantage over a normal SAE

The project can now say something much sharper than “some latents look positional.” It can say: we trained a model on Pythia-160M layer 3 with a smaller position dictionary and a larger content dictionary, and we can measure what each side contributes, what stays private, and what only appears when the two are combined.

What still has to be proved against normal SAEs

The project still needs a direct matched standard-SAE comparator before it can make the strongest publication claim. So the benefit today is clearest on interpretive structure and testability, not yet on every downstream score.

Short version: a normal SAE gives one undifferentiated feature soup. The current MSAE gives two named soups with different capacities, explicit pressure not to overlap, and a way to ask much more targeted scientific questions about what each side is doing.

Key Findings

The strongest findings, stated as directly as possible

If someone only remembers a few things from this project, these are the findings that matter most. They are stronger than "we ran some promising pilots" and more specific than "MSAE seems interesting."

Finding 1: the basic premise survived serious stress testing

The position-vs-content split held up across seeds, across layers 3 and 4, and across three data regimes. The clearest evidence is the 92/92 perfect pass rate at the headline ranks and the 0/46 failure rate at the boundary rank.

Why that matters: this is the difference between a fragile demo and a real empirical gate. The project did not just find one lucky configuration.

Finding 2: the project found a real operating regime, not just a theory

The work did not stop at probe geometry. The K=2 trainer passed smoke tests, resume tests, a 100M-token wave, and then a corrected 1B-token wave.

Why that matters: this turns MSAE from an idea about how things might work into an actual trainable system with a usable experimental stack.

Finding 3: the incoherence regularizer is not cosmetic

In the matched-seed comparison, the regularized run achieves much lower branch overlap than the no-regularizer control. The approximate 3.3x incoherence reduction is the cleanest causal evidence in the current project.

Why that matters: it answers the obvious skeptic question, "did you really learn two different branches, or just train two SAEs side by side?"

Finding 4: separation improved more clearly than reconstruction

The regularized runs are better on branch specialization, but slightly worse on reconstruction than the matched no-inc control. So the present evidence is a tradeoff story, not an everything-got-better story.

Why that matters: the project now has a precise modeling question to solve next, instead of a vague "keep scaling and hope."

Finding 5: the first split may not be the whole story

The PCC follow-up suggests that some syntax-like information may not live neatly inside a private position branch or a private content branch. It may partly live in shared or interaction-heavy structure.

Why that matters: even a successful K=2 decomposition may be only the first layer of the full representational story.

Finding 6: semantics currently looks more content-private than syntax

In the ongoing PCC analysis, semantic families mostly remain content-private, while some syntax families retain modest positive joint gains under stronger controls.

Why that matters: this is exactly the kind of asymmetry that could motivate later multi-branch or structured-branch designs.

Implications

What these findings imply for the science, not just the code

Implication 1: some SAE failures may be geometry mismatches

The results support the idea that at least part of the SAE problem is not just bad optimization or insufficient width. It may be that one dictionary is being asked to model signals with genuinely different geometric structure.

Implication 2: separation is a measurable target, not just a qualitative feeling

Because the project used explicit gates, holdouts, and controls, it can talk about separation as something tested quantitatively rather than narrated after the fact.

Implication 3: the next bottleneck is now sharply defined

The main open question is no longer "does MSAE basically work?" The main open question is "what is the best tradeoff between cleaner specialization and faithful reconstruction?"

Implication for Paper 1

Paper 1 now has a credible empirical backbone. The project can reasonably claim that a position/content demixing regime exists and is trainable. What it still needs is the strongest publication-facing comparator work, especially against a matched standard SAE baseline.

Implication for Paper 2

Paper 2 is no longer motivated by pure speculation. It is motivated by a concrete observation: K=2 can separate branches, but K=2 may still leave structured residuals, tradeoffs, and shared signal that a richer decomposition might handle better.

Implication for interpretability practice

If MSAE keeps working, it suggests that future interpretability tools may need to treat "what kind of structure is this?" as a first-class design question, rather than assuming every interpretable thing should be a sparse one-dimensional feature.

Implication for skepticism

The current evidence does not justify saying standard SAEs are obsolete or that MSAE already wins everywhere. It does justify saying that the multiple-dictionary approach has earned the right to be taken seriously as a competing research direction.

The most important strategic implication: the project should not spend its next large block of effort merely repeating the same K=2 run at larger scale. The stronger move is targeted follow-up: matched SAE comparison, small regularization calibration, and careful PCC control work.

What changed because of these findings

  • Layer 3 became the default Paper 1 site.
  • Ranks 8 and 16 became the headline regime.
  • The no-inc control became scientifically important, not just a formality.
  • The project shifted from premise validation to tradeoff analysis.

What would count as the next real upgrade

  • Show that MSAE beats or matches a standard SAE in a fair head-to-head comparison.
  • Show that the separation is useful for downstream interpretability tasks, not just internal geometry metrics.
  • Show whether shared syntax-like crossover structure is robust enough to justify a new branch family.
Bridge Program

PCC: the new question about shared crossover structure

After separating position-private and content-private signal, the team asked a new question: what if some important linguistic structure, especially syntax, is not private to either branch, but shared between them?

Emerging analysis, not a headline result Based on existing checkpoints, not a new PCC model

How to read this section: PCC matters because it may explain what the current K=2 split still misses. But it is a follow-on interpretation program, not stronger evidence than the pre-K2 gate or the 1B-token K=2 run.

PCC stands for

Position-Content Crossover. The hypothesis is that some structure may depend on both where something is and what it is.

What is being tested

Whether syntax looks more "joint" or shared, while semantics stays more content-private.

Why not train a new model immediately?

The team chose to begin with analysis on existing checkpoints so it could measure the signal first before committing to a new architecture.

A dense third branch for dark matter, broader K-component experiments, SAEBench, and the difficult 113-task probing benchmark.

What Paper 3 would add

Subspace-valued atoms and multiscale branches for cases where even K linear branches are not enough.

Takeaways

The simplest fair summary of the whole project

What MSAE has shown

  • The project's starting premise looks real: position and content can be separated in a robust way on the chosen model and layer.
  • The K=2 trainer is stable, resumable, and works all the way through a 1B-token run.
  • The incoherence regularizer clearly makes branches more specialized.
  • The project has opened a credible new question about shared syntax-like crossover structure.

What MSAE has not shown yet

  • It has not yet proved that MSAE is broadly better than the strongest SAE baselines on every benchmark.
  • It has not yet settled the best regularizer strength or penalty family.
  • It has not yet completed the larger K=3 and structured-branch programs.

Bottom line: today, the safest strong claim is that MSAE is a promising and empirically supported way to get cleaner branch separation inside transformer activations. The next phase is about deciding whether that cleaner separation turns into stronger downstream interpretability tools.
