retention on Jumbo; qualify the exact whole successor before any real source work.

  reinterpretation of partial/scoped SHIP as whole authority.

## Design-bank clarification and approach
DES-0203 keeps canonical placement on Jumbo; DES-0221 supplies child-repo topology.
No approved NORSPAN publication/retention alternative exists in the ledger.
Qualification v3 supplies the reviewed source-free JPC-1 design; owner explicitly
requires Jumbo. Native no-replace rename is unsupported on the current NFS.
Static integration audit identifies80 affected lines; two independently reproducible
scratch cleanup faults show that storage relocation alone is insufficient.

Retain deterministic stage+final hardlink pairs permanently (exact nlink2, original
owned-FD identity/digest, mandatory expected receipts and containing approval).
Retain **all initiated acquisition scratch on success and failure**; never run
recursive deletion, unlink, rename retirement or a quarantine move. This is an
explicit prospective schema/retention change, not pretending cleanup succeeded.
Approved ordinary source/code/config/review files remain unpaired nlink1.
Reserve/pin an explicit private Jumbo scratch root before network-start publication;
start marker must finish durability/owned-custody checks before first subprocess.

Alternatives: administrator-provided compatible Jumbo volume remains valid but
unavailable; it would not fix foreign scratch deletion. Checked-then-unlink cleanup,
retry-on-ENOTEMPTY, rename fallback or ignoring extra objects are rejected. A future
garbage-collection policy is OUT OF SCOPE; no retained subject may be removed here.

Placement is not yet approved: exact destinations/mount/dev/permissions/capacity/
retention/recovery and required server guarantees need review. Administrator unknowns
are recorded in storage-msae-jumbo-administrator-request.md. Unavailable required
evidence blocks production even if synthetic implementation work is green.
